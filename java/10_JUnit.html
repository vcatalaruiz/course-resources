    Testing con JUnit

    1. Introducción a JUnit

    JUnit es un framework de testing o pruebas unitarias para Java. Permite escribir y ejecutar pruebas automatizadas de forma sencilla y estructurada. Es el framework más popular en el mundo Java y forma parte esencial del desarrollo ágil y de la metodología Test-Driven Development (TDD).

    1.1. ¿Qué es una prueba unitaria?

    Una prueba unitaria es una prueba automatizada que verifica que una pequeña parte del código (una unidad, típicamente un método) funciona correctamente de forma aislada.

    • Verifica el comportamiento esperado de un método o clase
    • Se ejecuta de forma automática
    • Proporciona retroalimentación inmediata sobre errores
    • Facilita la refactorización segura del código
    • Documenta el comportamiento esperado del código

    1.2. Propósitos de JUnit

    Propósito Descripción
    Validación Verificar que el código produce los resultados esperados
    Regresión Detectar cambios indeseados tras modificaciones
    Documentación Mostrar cómo se usa correctamente el código
    Diseño Mejorar la estructura y modularidad del código
    Confianza Aumentar la seguridad al realizar cambios

    3. Anotaciones principales de JUnit 4

    3.1. @Test

    Marca un método como un caso de prueba. JUnit ejecutará todos los métodos anotados con @Test. 

    
import org.junit.Test;

public class CalculadoraTest {
    
    @Test
    public void testSuma() {
        // Código de prueba
        System.out.println("Test de suma ejecutándose...");
    }
}

    3.2. @Before y @After

    @Before se ejecuta antes de cada test. @After se ejecuta después de cada test. Útil para setup y cleanup de recursos. 

    
import org.junit.Before;
import org.junit.After;
import org.junit.Test;

public class CalculadoraTest {
    private Calculadora calc;
    
    @Before
    public void setUp() {
        calc = new Calculadora();
        System.out.println("Setup: Inicializando calculadora");
    }
    
    @Test
    public void testSuma() {
        int resultado = calc.sumar(5, 3);
        System.out.println("Resultado: " + resultado);
    }
    
    @After
    public void tearDown() {
        calc = null;
        System.out.println("Teardown: Liberando recursos");
    }
}

    3.3. @BeforeClass y @AfterClass

    Se ejecutan una única vez para toda la clase de test (antes de todos los tests y después de todos). Deben ser métodos static. 

    
import org.junit.BeforeClass;
import org.junit.AfterClass;
import org.junit.Test;

public class CalculadoraTest {
    
    @BeforeClass
    public static void setUpClass() {
        System.out.println("Inicializando clase de test (una sola vez)");
    }
    
    @Test
    public void testSuma() {
        System.out.println("Ejecutando test 1");
    }
    
    @Test
    public void testResta() {
        System.out.println("Ejecutando test 2");
    }
    
    @AfterClass
    public static void tearDownClass() {
        System.out.println("Finalizando clase de test (una sola vez)");
    }
}

    3.4. @Ignore

    Omite la ejecución de un test. Útil cuando el test no está listo o está roto. 

    
import org.junit.Ignore;
import org.junit.Test;

public class CalculadoraTest {
    
    @Test
    @Ignore("No implementado aún")
    public void testDivision() {
        // Este test no se ejecutará
    }
}

    3.5. Tabla resumen de anotaciones

    Anotación Descripción Frecuencia
    @Test Marca método como caso de prueba Por cada test
    @Before Ejecuta antes de cada test Antes de cada @Test
    @After Ejecuta después de cada test Después de cada @Test
    @BeforeClass Ejecuta una sola vez al principio (static) Una sola vez al inicio
    @AfterClass Ejecuta una sola vez al final (static) Una sola vez al final
    @Ignore Omite la ejecución del test Nunca

    4. Assertions - Verificaciones

    Los assertions son sentencias que verifican si el resultado obtenido coincide con el esperado. Si el assertion falla, el test se considera fallido.

    4.1. Principales métodos de Assert

    Método Descripción Ejemplo
    assertEquals() Verifica que dos valores sean iguales assertEquals(4, 2+2);
    assertTrue() Verifica que una condición sea true assertTrue(5 > 3);
    assertFalse() Verifica que una condición sea false assertFalse(5 < 3);
    assertNull() Verifica que un objeto sea null assertNull(obj);
    assertNotNull() Verifica que un objeto no sea null assertNotNull(obj);
    assertSame() Verifica que dos referencias apunten al mismo objeto assertSame(obj1, obj2);
    fail() Fuerza el fallo del test fail("No debería llegar aquí");

    4.2. Ejemplos de Assertions

    
import org.junit.Test;
import static org.junit.Assert.*;

public class AssertionsTest {
    
    @Test
    public void testAssertEquals() {
        // Verifica que el resultado sea exactamente 4
        assertEquals(4, 2 + 2);
        assertEquals("Esperado", "Esperado");
    }
    
    @Test
    public void testAssertTrue() {
        // Verifica que la condición sea verdadera
        assertTrue(5 > 3);
        assertTrue("El número es positivo".length() > 0);
    }
    
    @Test
    public void testAssertFalse() {
        // Verifica que la condición sea falsa
        assertFalse(5 < 3);
        assertFalse("".isEmpty() == false);
    }
    
    @Test
    public void testAssertNull() {
        String texto = null;
        assertNull(texto);
    }
    
    @Test
    public void testAssertNotNull() {
        String texto = "Hola";
        assertNotNull(texto);
    }
    
    @Test
    public void testAssertWithMessage() {
        // Assertions con mensaje personalizado
        assertEquals("El resultado debe ser 4", 4, 2 + 2);
        assertTrue("5 debe ser mayor que 3", 5 > 3);
    }
}

    5. Ejemplo completo: Primer Test

    5.1. Clase a probar: Calculadora

    
// Calculadora.java
public class Calculadora {
    
    public int sumar(int a, int b) {
        return a + b;
    }
    
    public int restar(int a, int b) {
        return a - b;
    }
    
    public int multiplicar(int a, int b) {
        return a * b;
    }
    
    public int dividir(int a, int b) {
        if (b == 0) {
            throw new IllegalArgumentException("No se puede dividir por cero");
        }
        return a / b;
    }
}

    5.2. Clase de test: CalculadoraTest

    
// CalculadoraTest.java
import org.junit.Before;
import org.junit.After;
import org.junit.Test;
import static org.junit.Assert.*;

public class CalculadoraTest {
    
    private Calculadora calc;
    
    @Before
    public void setUp() {
        // Se ejecuta antes de cada test
        calc = new Calculadora();
        System.out.println("Inicializando calculadora para test...");
    }
    
    @Test
    public void testSuma() {
        int resultado = calc.sumar(5, 3);
        assertEquals("5 + 3 debe ser 8", 8, resultado);
    }
    
    @Test
    public void testResta() {
        int resultado = calc.restar(10, 3);
        assertEquals("10 - 3 debe ser 7", 7, resultado);
    }
    
    @Test
    public void testMultiplicar() {
        int resultado = calc.multiplicar(4, 5);
        assertEquals("4 * 5 debe ser 20", 20, resultado);
    }
    
    @Test
    public void testDividir() {
        int resultado = calc.dividir(20, 4);
        assertEquals("20 / 4 debe ser 5", 5, resultado);
    }
    
    @Test(expected = IllegalArgumentException.class)
    public void testDividirPorCero() {
        // Este test espera que se lance una excepción
        calc.dividir(10, 0);
    }
    
    @After
    public void tearDown() {
        // Se ejecuta después de cada test
        calc = null;
        System.out.println("Limpiando después del test...");
    }
}

    5.3. Ejecución del test

    Para ejecutar los tests en una IDE como Eclipse o IntelliJ:

    1. Click derecho en la clase de test → Run As → JUnit Test
    2. O usar Maven: mvn test
    3. O usar Gradle: gradle test

    6. Testing de excepciones

    6.1. Método 1: @Test(expected=...)

    Espera que un método lance una excepción específica. 

    
import org.junit.Test;

public class ExceptionTest {
    
    @Test(expected = IllegalArgumentException.class)
    public void testExceptionEsperada() {
        String[] array = new String[5];
        String valor = array[10]; // Lanzará ArrayIndexOutOfBoundsException
    }
    
    @Test(expected = NullPointerException.class)
    public void testNullPointerException() {
        String texto = null;
        texto.length(); // Lanzará NullPointerException
    }
}

    6.2. Método 2: try-catch

    Captura la excepción y verifica su tipo y mensaje. 

    
import org.junit.Test;
import static org.junit.Assert.*;

public class ExceptionTest {
    
    @Test
    public void testExceptionConMensaje() {
        try {
            int resultado = 10 / 0;
            fail("Debería haber lanzado ArithmeticException");
        } catch (ArithmeticException e) {
            assertEquals("/ by zero", e.getMessage());
            assertTrue(e.getMessage().contains("zero"));
        }
    }
}

    7. Buenas prácticas en Testing

    7.1. Principio AAA (Arrange-Act-Assert)

    Todo test debe seguir esta estructura para mayor claridad: 

    
@Test
public void testCalculoCompleto() {
    // Arrange (Preparar): Configurar datos
    Calculadora calc = new Calculadora();
    int numeroA = 10;
    int numeroB = 5;
    
    // Act (Actuar): Ejecutar la acción
    int resultado = calc.sumar(numeroA, numeroB);
    
    // Assert (Verificar): Comprobar el resultado
    assertEquals(15, resultado);
}

    7.2. Nombres de tests descriptivos

    Los nombres deben explicar qué se está probando: 

    
// ❌ Mal
@Test
public void test1() { }

@Test
public void testOK() { }

// ✅ Bien
@Test
public void testSumarDosNumerosPositivosRetornaResultadoCorreto() { }

@Test
public void testDividirPorCeroLanzaExcepcion() { }

    7.3. Un assert por test (cuando sea posible)

    Cada test debe verificar un único comportamiento: 

    
// ❌ Evitar: Múltiples verificaciones
@Test
public void testCalculadora() {
    assertEquals(4, calc.sumar(2, 2));
    assertEquals(0, calc.restar(2, 2));
    assertEquals(4, calc.multiplicar(2, 2));
}

// ✅ Preferir: Tests separados
@Test
public void testSuma() {
    assertEquals(4, calc.sumar(2, 2));
}

@Test
public void testResta() {
    assertEquals(0, calc.restar(2, 2));
}

@Test
public void testMultiplicar() {
    assertEquals(4, calc.multiplicar(2, 2));
}

    7.4. Tests independientes

    Los tests no deben depender unos de otros: 

    
// ❌ Evitar: Dependencias entre tests
@Test
public void testPrimero() {
    // configura algo global
}

@Test
public void testSegundo() {
    // depende del resultado de testPrimero
}

// ✅ Preferir: Tests autónomos
@Test
public void testPrimero() {
    Calculadora calc = new Calculadora();
    // test completamente independiente
}

@Test
public void testSegundo() {
    Calculadora calc = new Calculadora();
    // test completamente independiente
}

    7.5. Considerar casos límite

    Probar no solo casos normales sino también casos extremos: 

    
@Test
public void testSumaConNumerosPositivos() {
    assertEquals(5, calc.sumar(2, 3));
}

@Test
public void testSumaConNumerosNegativos() {
    assertEquals(-5, calc.sumar(-2, -3));
}

@Test
public void testSumaConCero() {
    assertEquals(5, calc.sumar(5, 0));
}

@Test
public void testSumaConGrandesNumeros() {
    assertEquals(2000000000L, calc.sumar(1000000000, 1000000000));
}

    8. Ejecución de tests

    8.1. Con Maven

    Ejecuta todos los tests del proyecto: 

    
# Ejecutar todos los tests
mvn test

# Ejecutar una clase de test específica
mvn test -Dtest=CalculadoraTest

# Ejecutar un método específico
mvn test -Dtest=CalculadoraTest#testSuma

# Ejecutar sin parar en fallos
mvn test -DskipTests=false

    8.2. Con Gradle

    
# Ejecutar todos los tests
gradle test

# Ejecutar tests con salida detallada
gradle test --info

# Ejecutar una clase de test
gradle test --tests CalculadoraTest

    8.3. En la IDE (Eclipse/IntelliJ)

    • Click derecho en la clase de test → Run As → JUnit Test
    • O click en el triángulo verde junto al nombre de la clase o método
    • Se abre la ventana "JUnit" mostrando resultados en verde (✓ ok) o rojo (✗ fallido)

    8.4. Reporte de tests

    Maven genera reportes en target/surefire-reports/ con información detallada sobre los tests ejecutados, incluyendo tiempos de ejecución y resultados.
