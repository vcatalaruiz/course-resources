4.1. Lenguaje SQL: estructura y sintaxis

SQL (Structured Query Language) permite consultar y gestionar bases de datos relacionales. Una consulta de selección combina cláusulas para indicar columnas, tabla, filtros y orden.

SELECT nombre, salario -- Indica las columnas que queremos mostrar
FROM empleados -- Indica la tabla de origen
WHERE salario > 30000 -- Conserva solo los salarios mayores que 30000
ORDER BY salario DESC; -- Ordena del salario más alto al más bajo
  • SELECT: columnas que se devuelven.
  • FROM: tabla o tablas consultadas.
  • WHERE: condición aplicada a cada fila.
  • ORDER BY: orden de presentación.

La consulta se escribe con un orden sintáctico fijo. No es necesario poner cada cláusula: WHERE y ORDER BY son opcionales.

4.2. Consultas simples con SELECT

Selecciona solo la información necesaria. El asterisco devuelve todas las columnas y es útil para explorar, pero en una consulta final es mejor enumerar las columnas.

--Devuelve el título y el salario de cada oferta
SELECT titulo, salario FROM Ofertas; -- Consulta todas las filas de Ofertas

-- Misma consulta con alias
SELECT titulo AS puesto, salario AS salario_euros FROM Ofertas;

AS crea un alias para mostrar un nombre legible en el resultado; no renombra permanentemente la columna.

Filtrar filas con WHERE

WHERE mantiene únicamente las filas que cumplen la condición. Los operadores de comparación habituales son =, <>, >, <, >= y <=.

 -- Consulta con intervalo
SELECT titulo, salario 
FROM Ofertas
WHERE salario >= 25000 AND salario <= 40000;

-- Consulta con límite
SELECT titulo, fecha_publicacion
FROM Ofertas
WHERE fecha_publicacion > '2024-01-01';

Una fecha ISO como AAAA-MM-DD es fácil de comparar y ordenar en columnas de tipo fecha.

Operadores de filtro: LIKE, IN y BETWEEN

  • LIKE busca patrones: % representa cero o más caracteres y _ representa uno.
  • IN comprueba si un valor coincide con una lista.
  • BETWEEN comprueba un intervalo e incluye ambos extremos.
-- Busca la palabra dentro del título
SELECT titulo
FROM Ofertas
WHERE titulo LIKE '%Ingeniero%'; 

-- Acepta cualquiera de las dos ciudades
SELECT titulo, ubicacion
FROM Ofertas
WHERE ubicacion IN ('Madrid', 'Barcelona'); 

-- Incluye salarios de 25000 y de 40000
SELECT titulo, salario
FROM Ofertas
WHERE salario BETWEEN 25000 AND 40000;

Operadores lógicos y aritméticos

  • AND: deben cumplirse todas las condiciones.
  • OR: basta con que se cumpla una condición.
  • NOT: invierte una condición.
  • Los operadores aritméticos +, -, * y / permiten calcular valores en el resultado.
-- Exige salario y ciudad coincidentes
SELECT titulo, salario 
FROM Ofertas
WHERE salario > 30000 AND ubicacion = 'Madrid'; 

-- Calcula una columna adicional con un 10 %
SELECT titulo, salario, salario * 1.10 AS salario_con_aumento 
FROM Ofertas -- Consulta la tabla Ofertas
WHERE salario IS NOT NULL; -- Evita calcular sobre salarios sin informar

Usa paréntesis para dejar clara la prioridad al combinar AND y OR, por ejemplo: (ubicacion = 'Madrid' OR ubicacion = 'Barcelona') AND salario > 30000.

Tratamiento de NULL y valores vacíos

NULL indica que no hay un valor conocido o informado. No se compara con = ni con <>; se comprueba con IS NULL o IS NOT NULL.

SELECT titulo, salario -- Muestra las ofertas sin salario informado
FROM Ofertas -- Consulta la tabla Ofertas
WHERE salario IS NULL; -- Busca valores nulos

SELECT titulo, descripcion -- Muestra título y descripción
FROM Ofertas -- Consulta la tabla Ofertas
WHERE descripcion IS NULL OR descripcion = ''; -- Busca nulo o texto vacío

Una cadena vacía ('') no es lo mismo que NULL. Si los datos pueden contener ambos, trata las dos situaciones.

Ordenar resultados con ORDER BY

ASC ordena de forma ascendente y es la opción predeterminada. DESC ordena de forma descendente. Se pueden indicar varias columnas para resolver empates.

SELECT titulo, salario, ubicacion -- Muestra tres columnas
FROM Ofertas -- Consulta las ofertas
ORDER BY salario ASC, titulo ASC; -- Ordena por salario y después por título


SELECT nombre, ciudad -- Muestra candidatos y su ciudad
FROM Candidatos -- Consulta la tabla Candidatos
ORDER BY ciudad DESC, nombre ASC; -- Ordena ciudad descendente y nombre ascendente

La posición de NULL en una ordenación depende del gestor. En MySQL se puede expresarla de forma portable con una primera clave, por ejemplo ORDER BY salario IS NULL, salario ASC, para colocar los nulos al final.

4.5. Consultas multitabla: JOIN

Un JOIN combina filas de tablas relacionadas mediante columnas con valores correspondientes, normalmente una clave primaria y una clave foránea.

SELECT o.titulo, e.nombre, o.ubicacion -- Muestra datos de la oferta y su empresa
FROM Ofertas AS o -- Usa o como alias de Ofertas
INNER JOIN Empresas AS e ON o.id_empresa = e.id_empresa; -- Conserva ofertas con empresa relacionada

Los nombres id_empresa, las tablas y sus relaciones son ejemplos. Sustitúyelos por los nombres que aparezcan en DESCRIBE y en la estructura real de la base.

INNER JOIN y LEFT JOIN

  • INNER JOIN: devuelve solo filas con coincidencia en ambas tablas.
  • LEFT JOIN: mantiene todas las filas de la tabla izquierda; las columnas sin coincidencia de la derecha aparecen como NULL.

LEFT JOIN, candidatos sin inscripción y OUTER JOIN

SELECT o.titulo, e.nombre -- Muestra todas las ofertas y su empresa si existe
FROM Ofertas AS o -- Conserva como lado izquierdo todas las ofertas
LEFT JOIN Empresas AS e ON o.id_empresa = e.id_empresa; -- Añade la empresa coincidente o NULL

SELECT c.nombre -- Busca candidatos sin inscripciones
FROM Candidatos AS c -- Conserva todos los candidatos
LEFT JOIN Inscripciones AS i ON i.id_candidato = c.id_candidato -- Busca sus inscripciones
WHERE i.id_candidato IS NULL; -- Devuelve solo candidatos sin coincidencia
  • RIGHT JOIN conserva las filas de la tabla derecha.
  • MySQL no ofrece FULL OUTER JOIN directamente; se puede combinar un LEFT JOIN con un RIGHT JOIN mediante UNION.

Para que un LEFT JOIN siga conservando filas sin coincidencia, ten cuidado al filtrar columnas de la tabla derecha en WHERE: el filtro puede descartar los registros con NULL.

4.6. Funciones de agregación

Las funciones de agregación calculan un resumen sobre varias filas:

  • COUNT(*): cuenta filas.
  • SUM(campo): suma valores.
  • AVG(campo): calcula la media.
  • MIN(campo) y MAX(campo): encuentran mínimo y máximo.
SELECT COUNT(*) AS total_ofertas -- Cuenta todas las ofertas
FROM Ofertas; -- Lee la tabla de ofertas

SELECT MIN(salario) AS salario_minimo, MAX(salario) AS salario_maximo -- Resume los salarios extremos
FROM Ofertas -- Lee la tabla de ofertas
WHERE salario IS NOT NULL; -- Ignora los salarios no informados

Las agregaciones, salvo COUNT(*), normalmente ignoran valores NULL. Si la consulta mezcla columnas normales y agregadas, usa GROUP BY.

Agrupar resultados con GROUP BY

GROUP BY crea grupos con el mismo valor de una o más columnas. Las funciones de agregación se calculan para cada grupo.

SELECT ubicacion, COUNT(*) AS numero_ofertas -- Cuenta ofertas de cada ubicación
FROM Ofertas -- Lee la tabla de ofertas
GROUP BY ubicacion -- Crea un grupo para cada ciudad
ORDER BY numero_ofertas DESC; -- Muestra primero las ciudades con más ofertas

SELECT ubicacion, AVG(salario) AS salario_medio -- Calcula el salario medio por ubicación
FROM Ofertas -- Lee la tabla de ofertas
WHERE salario IS NOT NULL -- Excluye salarios no informados antes de agrupar
GROUP BY ubicacion; -- Devuelve una fila por ubicación

Cada columna del SELECT que no esté dentro de una función de agregación debe incluirse en el GROUP BY.

Filtrar grupos con HAVING

WHERE filtra filas antes de agrupar. HAVING filtra los grupos después de calcular las agregaciones.

SELECT ubicacion, AVG(salario) AS salario_medio -- Calcula una media por ciudad
FROM Ofertas -- Lee las ofertas
WHERE salario IS NOT NULL -- Elimina salarios desconocidos antes del cálculo
GROUP BY ubicacion -- Agrupa las filas por ciudad
HAVING AVG(salario) > 30000 -- Conserva ciudades con media superior a 30000
ORDER BY salario_medio DESC; -- Ordena las medias de mayor a menor

Recuerda: filtra una fila por su salario con WHERE salario > ...; filtra un grupo por su media con HAVING AVG(salario) > ....

4.7. Subconsultas en WHERE y SELECT

Una subconsulta es una consulta dentro de otra. Puede calcular un valor de referencia, comprobar pertenencia o añadir una columna calculada.

SELECT titulo, salario -- Muestra título y salario de cada oferta
FROM Ofertas -- Consulta las ofertas
WHERE salario > (SELECT AVG(salario) FROM Ofertas WHERE salario IS NOT NULL); -- Compara con la media global

SELECT titulo, salario, (SELECT AVG(salario) FROM Ofertas WHERE salario IS NOT NULL) AS media_global -- Añade la media en cada fila
FROM Ofertas; -- Devuelve todas las ofertas

La primera subconsulta devuelve un único valor (la media). La consulta exterior utiliza ese resultado como parte del filtro.

Subconsultas en FROM y subconsultas correlacionadas

SELECT resumen.ubicacion, resumen.total_ofertas -- Muestra los resultados calculados por la subconsulta
FROM ( -- Inicia una tabla derivada
    SELECT ubicacion, COUNT(*) AS total_ofertas -- Cuenta las ofertas por ciudad
    FROM Ofertas -- Consulta las ofertas
    GROUP BY ubicacion -- Crea un grupo por ciudad
) AS resumen -- Asigna un alias obligatorio a la tabla derivada
WHERE resumen.total_ofertas > 2; -- Conserva ciudades con más de dos ofertas

Una subconsulta correlacionada hace referencia a una fila de la consulta exterior. Se evalúa en relación con esa fila.

SELECT e.nombre -- Muestra el nombre de cada empresa
FROM Empresas AS e -- Recorre las empresas
WHERE EXISTS ( -- Comprueba si existe al menos una fila relacionada
    SELECT 1 -- Solo interesa comprobar la existencia
    FROM Ofertas AS o -- Busca ofertas
    WHERE o.id_empresa = e.id_empresa -- Relaciona la oferta con la empresa actual
); -- Finaliza la comprobación

Asigna siempre un alias a una subconsulta usada en FROM. Usa EXISTS cuando solo necesites comprobar si hay filas relacionadas.

4.8. Vistas

Una vista es una consulta guardada que se utiliza como una tabla virtual. Puede simplificar consultas repetidas o presentar un conjunto de datos más concreto.

CREATE VIEW ofertas_salario_alto AS -- Guarda una vista con ofertas seleccionadas
    SELECT id_oferta, titulo, salario, ubicacion -- Expone solo estas columnas
    FROM Ofertas -- Usa Ofertas como fuente
    WHERE salario > 30000; -- Limita la vista a salarios mayores de 30000

SELECT titulo, salario -- Consulta las columnas necesarias
FROM ofertas_salario_alto -- Lee la vista guardada
ORDER BY salario DESC; -- Ordena por salario descendente

Una vista sencilla sobre una sola tabla y sin agregaciones suele ser actualizable. Las vistas con agrupaciones, funciones agregadas, DISTINCT o uniones complejas pueden no serlo.

Modificar, reemplazar y eliminar vistas

CREATE OR REPLACE VIEW ofertas_salario_alto AS -- Crea o sustituye la definición de la vista
    SELECT id_oferta, titulo, salario, ubicacion -- Mantiene las columnas necesarias
    FROM Ofertas -- Usa la tabla original
    WHERE salario > 35000; -- Actualiza el criterio de selección

DROP VIEW IF EXISTS ofertas_salario_alto; -- Elimina la vista si existe

DROP VIEW elimina la definición de la vista, no los datos de la tabla original. Antes de usar UPDATE o DELETE sobre una vista, confirma que es actualizable y que la operación afecta a las filas esperadas.

4.9. Optimización de consultas

Optimizar busca reducir el trabajo que realiza el gestor sin cambiar el resultado correcto de la consulta.

  • Seleccionar las columnas necesarias en vez de usar SELECT *.
  • Filtrar con condiciones claras y aprovechar índices en columnas buscadas con frecuencia.
  • Limitar resultados con LIMIT cuando solo se necesita una muestra.
  • Usar EXISTS cuando baste con comprobar que hay filas relacionadas.
  • Evitar aplicar funciones sobre una columna filtrada, porque puede impedir el uso de un índice.
  • Comparar el plan de ejecución antes y después de un cambio.

En este ejemplo se utiliza EXPLAIN para comprobar, antes y después, como funciona el índice:

EXPLAIN no devuelve los resultados de la consulta, sino el plan de ejecución que el gestor utilizará para procesarla.

EXPLAIN SELECT titulo, ubicacion -- Pide al gestor el plan de ejecución
FROM Ofertas -- Lee las ofertas
WHERE ubicacion = 'Madrid'; -- Filtra por la ubicación indicada

CREATE INDEX idx_ofertas_ubicacion ON Ofertas (ubicacion); -- Añade un índice para búsquedas por ubicación

EXPLAIN SELECT titulo, ubicacion -- Vuelve a solicitar el plan
FROM Ofertas -- Lee la misma tabla
WHERE ubicacion = 'Madrid'; -- Compara el plan para el mismo filtro

Un índice puede acelerar lecturas, pero ocupa espacio y añade trabajo al insertar, actualizar o borrar. No se debe crear un índice sin una necesidad comprobada.

Limitar resultados y escribir filtros eficientes

Cuando solo necesites una muestra, limita el número de filas devueltas. En filtros por fecha, compara directamente la columna con un intervalo en lugar de transformar cada valor.

SELECT titulo, fecha_publicacion -- Muestra el título y la fecha de la oferta
FROM Ofertas -- Consulta la tabla Ofertas
ORDER BY fecha_publicacion DESC -- Coloca primero las ofertas más recientes
LIMIT 10; -- Devuelve solo diez filas

SELECT titulo, fecha_publicacion -- Devuelve título y fecha
FROM Ofertas -- Consulta la tabla Ofertas
WHERE fecha_publicacion >= '2024-01-01' AND fecha_publicacion < '2025-01-01'; -- Filtra un intervalo sin transformar la columna

Para consultar si existe una relación, EXISTS expresa directamente esa intención. La elección entre EXISTS e IN depende de la consulta y del plan que produzca el gestor.

Leer el resultado de EXPLAIN

EXPLAIN muestra cómo planea ejecutar la consulta. En MySQL, revisa especialmente:

  • type: método de acceso; una búsqueda por índice puede ser más selectiva que recorrer toda la tabla.
  • possible_keys / key: índices candidatos y el índice elegido.
  • rows: estimación de filas que se leerán.
  • Extra: información adicional sobre filtros y operaciones.

Compara la misma consulta antes y después del índice. Explica qué cambia en key y rows; el plan depende del tamaño de los datos y de las estadísticas del servidor.

¿Qué has aprendido?

  • Una consulta se construye con cláusulas como SELECT, FROM, WHERE y ORDER BY.
  • Los operadores permiten filtrar por comparación, texto, intervalos, listas y valores nulos.
  • Los JOIN combinan tablas; LEFT JOIN conserva todas las filas del lado izquierdo.
  • Las agregaciones resumen los datos; GROUP BY agrupa y HAVING filtra grupos.
  • Las subconsultas y vistas organizan consultas reutilizables.
  • EXPLAIN ayuda a entender el plan; los índices se valoran según el uso real.

Glosario esencial

  • Alias: nombre temporal para una columna o tabla.
  • Agregación: cálculo de resumen como suma, media o recuento.
  • JOIN: combinación de filas relacionadas entre tablas.
  • NULL: ausencia de un valor conocido o informado.
  • Subconsulta: consulta anidada dentro de otra consulta.
  • Vista: consulta guardada que se presenta como tabla virtual.
  • Índice: estructura que puede ayudar a localizar filas con mayor rapidez.
  • Plan de ejecución: estrategia que el gestor prevé utilizar para ejecutar una consulta.

Actividad 2: consultas multitabla con JOIN y LEFT JOIN

Ejemplo guiado: título, empresa y ubicación

El primer paso es identificar las relaciones entre las tablas. En este caso Ofertas tiene una clave foránea id_empresa que apunta a Empresas. Por tanto, podemos unirlas con un INNER JOIN.

SELECT o.titulo, e.nombre AS empresa, o.ubicacion -- Elige columnas de ambas tablas
FROM Ofertas AS o -- Da un alias corto a Ofertas
INNER JOIN Empresas AS e ON o.id_empresa = e.id_empresa; -- Relaciona cada oferta con su empresa

Pasos para resolver las demás

  1. Dibuja o identifica las relaciones en las claves foráneas.
  2. Elige INNER JOIN cuando solo quieras coincidencias; elige LEFT JOIN para conservar también las filas sin relación.
  3. Para contar candidatos, combina inscripciones y ofertas, usa COUNT y agrupa por oferta.
  4. Para candidatos sin ofertas, usa LEFT JOIN y filtra la clave de inscripción con IS NULL.
  5. Para el caso Barcelona, filtra la ciudad de la empresa y excluye la ubicación de la oferta.

Los nombres de tablas y claves del ejemplo pueden diferir de la base de datos entregada. Ajusta id_empresa, id_candidato y id_oferta a las columnas reales.

Actividad 3: agregaciones y agrupación

Enunciado: resuelve ocho consultas usando COUNT, SUM, AVG, MAX, MIN, GROUP BY y HAVING

Ejemplo guiado: Número total de ofertas publicadas en la tabla Ofertas de cada empresa.

Para contar ofertas por empresa, agrupa por la columna de id_empresa y usa COUNT(*) para contar las filas de cada grupo. Ordena el resultado de mayor a menor.

SELECT id_empresa, COUNT(*) AS total_ofertas -- Cuenta las filas de cada grupo
FROM Ofertas -- Lee las ofertas publicadas
GROUP BY id_empresa -- Agrupa por empresa
ORDER BY total_ofertas DESC; -- Muestra primero las empresas con más ofertas

Cómo completar las otras consultas

  1. Empieza por la dimensión de agrupación: empresa, ubicación, ciudad o sexo.
  2. Escoge la función adecuada: cuenta filas, calcula media, máximo o mínimo.
  3. Añade HAVING solo para condiciones sobre el resultado agregado.
  4. Ordena los resultados por la medida calculada cuando lo solicite el enunciado.

Una columna del SELECT que no sea agregada debe aparecer en GROUP BY. Usa alias para que los resultados sean fáciles de interpretar.

Actividad 4: subconsultas, vistas y EXPLAIN

Enunciado: Mostrar todas las ofertas cuyo salario sea superior al salario promedio de todas las ofertas.

Ejemplo:Mostrar todas las ofertas cuyo salario sea superior al salario promedio de todas las ofertas.

SELECT id_oferta, titulo, salario, ubicacion -- Mantiene las columnas necesarias 
FROM Ofertas -- Consulta la tabla de ofertas
WHERE salario > (SELECT AVG(salario) FROM Ofertas); -- Compara con la media global usando una subconsulta escalar

Ejemplo: Crear una vista que muestre solo las ofertas con salario superior a 30000. Esta vista debe permitir UPDATE y DELETE sobre sus registros.

CREATE OR REPLACE VIEW ofertas_altas AS
SELECT id_oferta, titulo, salario, ubicacion
FROM Ofertas
WHERE salario > 30000;

Ejemplo: Crea una consulta con EXPLAIN

EXPLAIN SELECT e.nombre, o.titulo -- Solicita el plan de la consulta
FROM Empresas AS e -- Consulta empresas
INNER JOIN Ofertas AS o ON o.id_empresa = e.id_empresa -- Relaciona cada empresa con sus ofertas
WHERE o.ubicacion = 'Madrid'; -- Limita los resultados a Madrid

Completa la práctica

  1. Para candidatos en ciudades con ofertas, usa IN con una subconsulta que seleccione ubicaciones.
  2. Para añadir la media global, incorpora una subconsulta escalar en la lista de SELECT.
  3. Crea una vista simple de ofertas con salario superior a 30.000 y comprueba sus filas.
