Estructura de Proyectos y Colecciones en Dart

1. Creación de un proyecto en Dart

Un proyecto Dart tiene una estructura organizada donde se distribuyen los diferentes archivos que lo componen. Cada una de estas partes cumple una función específica sobre el proyecto, tales como el control de versionado, la gestión de librerías y las configuraciones del entorno.

1.1. Comandos de creación

Para crear un nuevo proyecto estructurado desde la terminal, ejecutamos el siguiente comando:


dart create "NOMBRE_PROYECTO"

1.2. Paquetes y Directorios Principales

Una vez generado el proyecto, se creará un árbol de directorios con la siguiente distribución[cite: 5]:


my_dart_project/
├── .dart_tool/          # Almacenamiento interno de herramientas (gestionado por Dart; no editar)
├── bin/                 # Scripts ejecutables de la línea de comandos
│   └── main.dart        # Punto de entrada principal para la ejecución (Entry point)
├── lib/                 # Código público principal compartido con otros proyectos
│   ├── src/             # Detalles de implementación privada e interna
│   │   └── internal.dart
│   └── my_library.dart  # API pública principal exportada para los usuarios externos
├── test/                # Pruebas de código unitarias y de integración
│   └── main_test.dart
├── CHANGELOG.md         # Historial detallado de cambios de versión del proyecto
├── LICENSE              # Texto de licencia de código abierto o propietaria
├── README.md            # Descripción general del proyecto y guía de uso
├── pubspec.lock         # Registro con las versiones exactas instaladas de cada dependencia (Bloqueo automático)
└── pubspec.yaml         # Dependencias solicitadas, recursos estáticos y metadatos del proyecto

2. Dependencias

Son paquetes de código externo (librerías, plugins o herramientas) creados por la comunidad o por el propio equipo de Dart para añadir funcionalidades a tu proyecto sin tener que programarlas desde cero.

El gestor de dependencias oficial de Dart se llama pub. Es la herramienta integrada en el ecosistema de Dart que se encarga de descargar, instalar, actualizar y resolver los conflictos de las librerías externas que tu proyecto necesita para funcionar.

2.1. El archivo pubspec.yaml

El archivo pubspec.yaml es la pieza central de metadatos del proyecto. Define la identidad de la aplicación e indica las restricciones del SDK y sus dependencias externas: 


name: mi_primer_proyecto
description: A sample command-line application.
version: 1.0.0

environment:
  sdk: '>=2.18.0 <3.0.0'

dependencies:
  path: ^1.8.0

dev_dependencies:
  lints: ^2.0.0
  test: ^1.16.0

3. Pruebas Unitarias

Las pruebas unitarias son fragmentos de código que verifican que funciones, métodos y clases de tu programa funcionan correctamente. Son esenciales para garantizar la calidad del código, detectar errores tempranamente y facilitar el mantenimiento del proyecto.

3.1. El paquete test

Dart proporciona el paquete test, que es el framework de pruebas oficial para crear y ejecutar pruebas unitarias. Generalmente, ya está incluido en el archivo pubspec.yaml como una dependencia de desarrollo: 


dev_dependencies:
  test: ^1.25.0

Si no está presente, puedes agregarlo manualmente o instalarlo desde la terminal:


dart pub add dev:test

3.2. Estructura de pruebas

Las pruebas se organizan en el directorio test/. Por convención, cada archivo de prueba debe terminar en _test.dart. La estructura recomendada es: 


test/
├── unit/
│   ├── calculadora_test.dart
│   ├── usuario_test.dart
│   └── validador_test.dart
├── integration/
│   └── app_integration_test.dart
└── fixtures/
    └── datos_prueba.dart

3.3. Estructura básica de una prueba

Una prueba unitaria en Dart tiene la siguiente estructura:


import 'package:test/test.dart';

void main() {
  group('Grupo de pruebas', () {
    setUp(() {
      // Se ejecuta antes de cada prueba
      print('Preparando prueba...');
    });

    tearDown(() {
      // Se ejecuta después de cada prueba
      print('Limpiando después de prueba...');
    });

    test('Descripción de lo que se prueba', () {
      // Arrange: Preparar los datos necesarios
      int a = 5;
      int b = 3;

      // Act: Ejecutar la acción a probar
      int resultado = a + b;

      // Assert: Verificar que el resultado es correcto
      expect(resultado, equals(8));
    });
  });
}

3.4. Ejecutar pruebas

Desde la terminal del proyecto, puedes ejecutar tus pruebas de varias formas:

Ejecutar todos los tests del proyecto: Si ejecutas el comando sin especificar una ruta, el gestor buscará de forma automática todos los archivos que terminen en _test.dart dentro de la carpeta test/.


# Ejecutar todas las pruebas
dart test

# Ejecutar un archivo de prueba específico
dart test test/calculadora_test.dart

# Ejecutar pruebas con filtro por nombre
dart test --name "Sumar"

# Ejecutar pruebas con salida detallada
dart test -v

Resumen de Estructura proyecto

  • Los proyectos Dart se estructuran con directorios fijos: bin/ para ejecución y lib/ para métodos genéricos.
  • El archivo pubspec.yaml centraliza el control de versiones del SDK y las dependencias del ecosistema.
  • Las pruebas unitarias utilizan el paquete test y se almacenan en el directorio test/ con archivos terminados en _test.dart.
  • Sigue el patrón AAA (Arrange, Act, Assert) para estructurar tus pruebas de manera clara y mantenible.
  • Usa matchers apropiados para hacer aserciones expresivas y readable en tus pruebas unitarias.
